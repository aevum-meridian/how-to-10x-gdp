# DOCUMENT 10.1 — API & OPENAPI SPECIFICATION
### The Versioned, Honest Public Interface

**System:** Joint · **Licenses:** both · **Tier:** 10 · **Maturity:** InDevelopment · **© Maher**

The public API is versioned (`/api/v1/…`), JSON, stateless, with idempotent writes (Idempotency-Key header), authenticated via the GAS adapter in front of Sanctum (first-party) and Passport (third-party OAuth2), authorized via Spatie permissions, and rate-limited per endpoint/identity. The surface includes: account and balance endpoints (balances returned with a verifiable proof, per the user's right to a verifiable history); idempotent transfer endpoints (proposed through the event contract, validated by Meridian); reserve mint/redeem (licensed-tunnel only, with proof-of-backing); contribution mint (requiring a valid quorum attestation); attestation submission (verifiers); the currency registry (read public; write governance-gated, refusing Core Riba policies); the transparency log (public, verifiable); bridge deposit/withdraw (membrane-filtered); the user's exportable verifiable history; and — uniquely and bindingly — `GET /api/v1/maturity` (the maturity endpoint every other surface must check) and `GET /api/v1/trade-off-register` (the machine-readable Trade-off Register). Every money value is a decimal string over `bigint` minor units; every capability the API exposes carries its maturity label. The full OpenAPI document is published so any OIDC/standards-compliant client can integrate, and it is the single source of truth for the API surface. Honest caveat: the API must never expose an endpoint for a Research-tier capability as though it were available (AVL-2.0 §A-§C.13) — the maturity endpoint is the binding check, and the OpenAPI spec marks each operation's maturity.
